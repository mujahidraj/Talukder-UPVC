1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) defines the functional and non-functional requirements for a website for Talukder uPVC Fittings Industries Ltd. The website will present the company's full uPVC pipe and fittings catalog in a modern, e-commerce-style browsing experience — with categories, product listings, product detail pages, search, filters, and a shopping-cart-like flow — but WITHOUT any purchase, payment, checkout, or online transaction capability. In place of "Buy", customers can save products to a Wishlist and submit product Enquiries / Quote Requests. The system also includes a full Admin Panel for content and catalog management, including CRUD operations and bulk import of products (Excel) and product images.
1.2 Scope
The system consists of two main applications sharing one product database:
Public Website (Storefront-style, no payment): Browsing, search, filtering, product details, wishlist, enquiry/quote requests, static/CMS pages, and optional customer accounts.
Admin Panel (Back office): Secure login, dashboard, product CRUD, bulk Excel import, bulk image upload, category management, enquiry management, CMS/content management, user & role management, and reporting.
The initial product catalog supplied by the client (Talukder_uPVC_Product_Catalog.xlsx) contains 243 products across 11 top-level categories and 21 sub-categories, and defines the baseline data model used throughout this document (see Section 6).

2. Overall Description
2.1 Product Perspective
The website looks and behaves like a modern B2B e-commerce catalog (category mega-menu, product grid, product detail page, filters, "Add to Wishlist", "Add to Enquiry List") but functionally there is no price checkout, no payment gateway, and no order fulfilment. The commercial conversion point is the Enquiry / Quote Request form, which is emailed/stored for the sales team to follow up manually or via phone/WhatsApp/email.
2.2 User Classes and Characteristics
The system supports exactly these three user classes. There is no visitor account registration or login on the public website — every catalog visitor is an anonymous Guest Visitor as described above.
2.3 Operating Environment
Public website: responsive web app, accessible on desktop, tablet, and mobile browsers (Chrome, Safari, Edge, Firefox — latest 2 versions).
Admin Panel: desktop-first responsive web app, accessible via a separate secured route (e.g. /admin) or subdomain.
Hosted on a standard LAMP/Node/cloud stack with HTTPS; a relational database stores structured product and enquiry data; object storage (or server file storage) holds product images.
2.4 Design & Implementation Constraints
No payment gateway, no order/checkout module, no shopping cart pricing logic — explicitly out of scope.
The initial catalog must be seeded from the supplied Excel file's 18 columns (Section 6); the schema must not lose any of these fields.
Bangla + English bilingual support is recommended given the target market, but can be phased (see Section 12, Future Enhancements) if not required for v1.
2.5 Assumptions & Dependencies
The client will supply high-resolution product images for bulk upload; the current catalog file has no embedded images, so an image-sourcing/photography step is a dependency, not a development task.
The client will provide/approve category and sub-category naming (already partially defined by the source catalog).
Enquiry notifications will use email (SMTP) at minimum; SMS/WhatsApp integration is an optional future enhancement.

4. Functional Requirements — Admin Panel
4.1 Authentication & Access Control
Secure admin login (email/username + password, hashed & salted), optional 2FA.
Role-based access control: Super Admin, Admin/Catalog Manager, and Sales/Enquiry Staff (configurable roles).
Session timeout, forced logout, password policy, account lockout after repeated failed attempts.
4.2 Dashboard
Summary widgets: total products, products by status, total categories, new enquiries (today/week), wishlist activity, low-content/missing-image products.
Recent activity feed and quick links to common tasks.
4.3 Product Management (CRUD)
Create: form covering all 18 catalog fields (Section 6) with validation (required fields, allowed size/color formats, unique Product Code).
Read: searchable/filterable/sortable product data table (server-side pagination) with column show/hide.
Update: edit any field; edit history / "last modified by & when".
Delete: soft-delete (archive) by default, with a separate permanent-delete action restricted to Super Admin; bulk select + bulk status change/delete.
Duplicate/Clone product (to speed up entering size variants of the same item).
Rich-text editor for Description; repeatable list inputs for Features and Applications (stored structured, not just semicolon strings).
4.4 Bulk Product Upload (Excel/CSV Import)
Downloadable import template pre-mapped to the 18 columns of the source catalog (Category, Sub-Category, Product Code, Product Name, Fitting/Connection Type, Size, Thickness (mm), Length, Color, Class/Type, Material, Brand/Manufacturer, Description, Features, Applications, Status, Source Page (Catalog), Product Image [filename reference]).
Upload .xlsx/.csv; system validates each row (required fields, duplicate Product Code detection, invalid Status values, invalid category references) before committing.
Pre-import preview screen showing row-by-row validation results: rows to be Created, rows to be Updated (matched by Product Code), and rows with Errors (with reason).
Import modes: "Insert new only", "Update existing only", or "Insert & Update (upsert)".
Downloadable error report (Excel) for failed rows so the admin can fix and re-upload.
Import job history log: file name, uploaded by, date/time, rows processed/succeeded/failed, rollback option for the most recent import.
4.5 Bulk Image Upload
Drag-and-drop multi-file image upload (JPG/PNG/WebP), with client-side compression and server-side resizing (thumbnail, medium, full/zoom sizes).
Auto-association of images to products by filename-to-Product-Code matching (e.g. 31806.jpg → Product Code 31806), with a manual re-assign step for unmatched files.
Support multiple images per product with drag-to-reorder and a designated "primary/cover" image.
Media Library: central, searchable repository of all uploaded images, showing which are linked/unlinked to products, with bulk delete of unused images.
4.6 Category & Sub-Category Management
CRUD for categories/sub-categories (name, slug, description, image/icon, display order, show/hide on menu).
Move/re-parent sub-categories; reassign products in bulk when a category is renamed or merged.
4.7 Enquiry (RFQ) Management
List/table of all enquiries with filters (status, date range, source page, assigned staff).
Enquiry detail view: customer info, product line items, quantities, notes.
Status workflow: New → In Progress → Quoted → Won/Closed → Lost, with internal notes and staff assignment.
Export enquiries to Excel/CSV; email the customer directly from the enquiry record (with a logged thread).
4.8 Wishlist Insights
Aggregate, anonymized report of most-wishlisted products/categories to inform sales & inventory decisions (no exposure of personal data beyond what's needed).
4.9 User / Customer Management
View registered customers, their wishlist and enquiry history; ability to deactivate an account.
Manage Admin users: create/edit/deactivate, assign roles/permissions (Super Admin only).
4.10 CMS / Content Management
Manage homepage banners/carousel, featured product selection, static pages (About, Terms, Privacy), and downloadable catalog PDF.
Basic SEO fields per page/category/product: meta title, meta description, URL slug.
4.11 Reports & Analytics
Product performance (views, wishlist adds, enquiries generated) per product/category.
Enquiry conversion funnel and volume trends over time.
Exportable reports (Excel/PDF).
4.12 System / Activity Log
Audit trail of admin actions (who changed what product/field and when), bulk import history, and login history — for accountability and rollback support.
5. Data Model — Product Entity
The following fields are derived directly from the client-supplied catalog file (Talukder_uPVC_Product_Catalog.xlsx, sheet "Products", 243 rows) and form the mandatory baseline schema for the Product entity. Additional system fields (id, slug, created_at, updated_at, created_by, view_count, etc.) will be added by the implementation team as needed.
Note: "Features" and "Applications" are semicolon-delimited free text in the source file (e.g. "Water Supply Systems; Irrigation Systems; ..."); the system should parse and store these as structured lists so they render as bullet points and remain filterable, while the bulk-import template continues to accept the same semicolon-delimited format for compatibility with the client's existing file.

6. Non-Functional Requirements
6.1 Performance
Public pages should load in under 3 seconds on a typical broadband/4G connection; product listing queries should be paginated/indexed for sub-second response with the full 243+ product catalog and beyond.
Bulk import of 500+ rows should complete (with validation) within a reasonable background-job time, with progress feedback rather than blocking the admin UI.
6.2 Security
HTTPS everywhere; hashed & salted passwords; role-based access control on all admin routes/APIs.
Input validation and sanitization on all public forms (enquiry, search) to prevent injection/XSS; rate limiting and spam/bot protection on the enquiry form.
File-upload validation (type/size limits, virus scan if feasible) for both Excel imports and images.
6.3 Usability & Accessibility
Fully responsive across mobile, tablet, desktop; e-commerce-familiar UX patterns (mega menu, filters, grid/list, Wishlist, cart-like enquiry list).
WCAG 2.1 AA-oriented accessibility (alt text on images, keyboard navigation, sufficient color contrast).
6.4 SEO
Clean, human-readable URLs; server-side rendering or pre-rendering for product/category pages; sitemap.xml and robots.txt; structured data (schema.org Product markup, minus price/offer fields).
6.5 Scalability & Maintainability
Architecture should comfortably support catalog growth well beyond the current 243 products/11 categories without redesign.
Clear separation between the public site and Admin Panel; documented REST/GraphQL API layer between front end and back end.
6.6 Reliability & Backup
Regular automated database backups; ability to restore a prior product-data state (paired with the ImportJob rollback capability in Section 4.4).
Staging/testing environment separate from production before major catalog imports or design changes.
6.7 Browser & Device Support
Latest two versions of Chrome, Firefox, Safari, Edge; iOS Safari and Android Chrome for mobile.

8. Key Workflows
8.1 Enquiry / RFQ Workflow
Customer browses catalogs and adds one or more products to the Enquiry List (cart-like), or uses Quick Enquiry on a single product.
Customer fills in the Enquiry form (contact details, quantities, notes) and submits.
System stores the enquiry (status = New), emails a confirmation to the customer, and notifies assigned sales/admin staff.
Admin reviews the enquiry, updates status (In Progress → Quoted → Won/Closed/Lost), and communicates the actual price/quote to the customer outside or alongside the system (email/phone).
Enquiry record remains in the customer's "My Enquiries" history (if registered) and in Admin reporting.
8.2 Bulk Import Workflow
Admin downloads the import template or exports current products to Excel for editing.
Admin uploads the completed Excel/CSV file and selects import mode (Insert / Update / Upsert).
System validates all rows and shows a preview (Create / Update / Error counts) before committing.
Admin confirms; system processes the import as a background job and shows progress/results, with a downloadable error report for any failed rows.
Import is logged in Import Job history; the most recent import can be rolled back if needed.
8.3 Bulk Image Upload Workflow
Admin selects a batch of image files named after Product Codes (e.g. 31806.jpg, 31806-2.jpg).
System auto-matches images to existing products by Product Code and shows a match preview; unmatched files are flagged for manual assignment.
Admin confirms; system resizes/optimizes images and attaches them to the correct products, letting the admin set the primary image and reorder the gallery.
9. Suggested Technology Stack (Non-Binding)
The core stack is confirmed as Node.js (NestJS) for the backend, ReactJS for the frontend, and PostgreSQL for the database; the remaining supporting layers below are suggestions, and the development team may substitute equivalent technologies based on team expertise and hosting constraints.
10. Assumptions, Constraints & Out of Scope
10.1 Assumptions
Pricing is not displayed publicly; if the client later wants indicative pricing shown (without checkout), this can be added as a simple optional field per product.
The client's sales team will handle actual price negotiation and order fulfilment outside the website (phone/email/in person), using enquiry data captured by the system.
10.2 Constraints
No payment gateway integration, no order management/fulfilment/shipping module, no invoicing — these are explicitly excluded from this SRS.
Initial content quality (images, refined descriptions) is bounded by what the client can supply; the Admin Panel must make it easy to complete/correct this data post-launch.
10.3 Out of Scope (v1)
Online payment / checkout / shopping cart pricing.
Real-time inventory/stock tracking (can be simulated with a simple "Status" field as in the source catalog).
Multi-currency or multi-country logistics.
11. Future Enhancements (Phase 2+)
Bilingual site (Bangla/English) with per-field translations.
Dealer/distributor locator with map integration.
Live chat / chatbot for instant product Q&A.
Customer reviews/ratings on products (non-transactional).
Optional "indicative price" display and/or a full e-commerce checkout module, should the business model evolve.
SMS/WhatsApp Business API notifications for enquiry status updates.
Advanced analytics (heatmaps, funnel tracking) and A/B testing on CTAs.
